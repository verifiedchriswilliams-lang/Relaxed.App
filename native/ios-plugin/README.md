# Premium StoreKit plugin (native iOS)

The native half of the $4.99 one-time unlock. The web side is done
(`lib/entitlement.ts` calls `Capacitor.Plugins.Premium`); these files make the
purchase real. Everything here runs in Xcode on your Mac, the `ios/` project
isn't in this repo (it's generated by `npx cap add ios`).

Files:
- `PremiumPlugin.swift` — StoreKit 2 implementation (getEntitlement / purchase / restore + a live updates listener).
- `PremiumPlugin.m` — makes the Swift class conform to Capacitor's bridge protocol as `Premium`.
- `MainViewController.swift` — a `CAPBridgeViewController` subclass that **registers** the plugin (required — see below).
- `Premium.storekit` — a StoreKit test config so you can buy/restore in the simulator without App Store Connect.

## 1. Add the plugin to the Xcode project

```bash
npm run ios:sync        # make sure ios/ is current
npm run ios:open        # opens ios/App/App.xcworkspace
```

- Drag **`PremiumPlugin.swift`**, **`PremiumPlugin.m`**, and
  **`MainViewController.swift`** into the **App** group in Xcode (the folder with
  `AppDelegate.swift`). When prompted, choose **Copy files to destination** and
  add them to the **App** target.
- If Xcode offers to create an **Objective-C bridging header**, say **yes** (it's
  needed so the `.m` can see Capacitor). If you already have one, no change.

### 1a. Register the plugin (REQUIRED — Capacitor 6+)

Capacitor 6+ does **not** auto-discover app-local plugins. The bridge registers
only its built-ins plus the npm plugins in `capacitor.config.json`'s
`packageClassList`; a plugin that lives in the App target (like this one) is
never in that list, so it must be registered by hand. `MainViewController.swift`
(a `CAPBridgeViewController` subclass) does that in `capacitorDidLoad()` — but it
only runs if the app actually instantiates it as its root view controller.

**This Capacitor template builds the root VC in code, not from the storyboard.**
So the registration hook is wired in `SceneDelegate.swift`, not via a storyboard
custom class. In `ios/App/App/SceneDelegate.swift`, inside
`scene(_:willConnectTo:options:)`, change:

```swift
window?.rootViewController = CAPBridgeViewController()
```
to:
```swift
window?.rootViewController = MainViewController()
```

(`MainViewController` is in the App target, so no import is needed.)

> Note: `ios/` is generated by `npx cap add ios` and is **not** committed, so this
> one-line edit must be re-applied after a fresh `cap add ios`. If a future
> template instead uses the storyboard for its root VC, set the bridge view
> controller's **Custom Class** to `MainViewController` in Main.storyboard rather
> than editing SceneDelegate.

Without this step there are **no lock glyphs and no "more voices"** in the app:
the web layer probes the bridge for `Premium`, finds nothing, and treats the
device as "no purchase possible" (premium stays free/hidden). It compiles fine
either way — the symptom is purely at runtime. To verify at runtime, open the
web inspector console on the running app and check
`window.Capacitor.isPluginAvailable('Premium')` is `true`.

## 2. Capability + product ID

- App target → **Signing & Capabilities** → **+ Capability** → **In-App Purchase**.
- The product ID in `PremiumPlugin.swift` is **`app.relaxed.premium`**. It must
  match the product you create in App Store Connect (step 4). Change both together
  if you want a different ID.

## 3. Test in the simulator (no App Store Connect needed)

- Drag **`Premium.storekit`** into the project (add to the App target).
- Product → **Scheme → Edit Scheme → Run → Options → StoreKit Configuration** →
  select **Premium.storekit**.
- Run the app, pick a premium bed/voice or ∞, tap **Begin → $4.99 once**. The
  StoreKit test sheet appears; buy it and the locks disappear. Test **Restore
  purchase**, and use the **Debug → StoreKit → Manage Transactions** window to
  clear the purchase and re-test the locked state.

## 4. App Store Connect (for the real product)

- App Store Connect → your app → **Monetization → In-App Purchases → +**.
- Type **Non-Consumable**, Reference Name "Premium Unlock", Product ID
  **`app.relaxed.premium`**, price **Tier for $4.99**.
- Add the localized display name / description and a **review screenshot** of the
  unlock sheet (App Review requires one).
- Submit the IAP **with** the 1.3 build (a new IAP is reviewed alongside the app
  version the first time).

## 5. Ship

- Remove the `Premium.storekit` scheme setting before archiving (so the real
  App Store products are used, not the test config).
- Archive + upload as usual (see [../../docs/ios-build.md](../../docs/ios-build.md)),
  attach to the 1.3 version, submit. Per the plan, submit 1.3 only after 1.2.2 is
  approved.

## How the two halves talk

- JS → native: `Capacitor.Plugins.Premium.getEntitlement() / purchase() / restore()`,
  each resolving `{ entitled: boolean }`.
- native → JS: the plugin fires **`entitlementChanged`** with `{ entitled }` when a
  transaction lands out of band (Ask to Buy, another device, a refund).
  `lib/entitlement.ts` subscribes and updates the UI live.
- The entitlement is cached on-device (`relaxed.premium.v1`) so the UI is correct
  offline and instantly on next launch; StoreKit remains the source of truth.
